# 后续发展方向

基于统一任务管理落地后的代码现状，建议按以下方向推进。第三项已实现，其余仍为规划。

## 1. 发布前验证与执行边界

先执行 `task-management.md` 的实机清单，重点验证录屏文件完整性、拔线恢复、VPN 授权和退出清理。
将桌面回归、辅助 APK 构建/测试、内置 APK 版本一致性检查接入 CI。
下一批任务适配器可接入 APK 安装、文件传输和 CLog 导出；对可能已经在设备端生效的写操作，明确“取消请求不等于回滚”，不做盲目重试。

验收：同一套主流程在目标 Android 版本和常用厂商设备上有可复查的记录，发布包与源码构建产物一致。

## 2. 测试会话与统一产物

当前任务已有设备、应用、ID、开始/结束时间和输出路径，适合在其上增加 `sessionId` 和产物清单。
一次会话组合日志、录屏、弱网和诊断；部分任务启动失败时，停止本次新启动的任务并保留已采集的数据。

最小交付：选择设备/应用 → 开始会话 → 标记问题 → 结束 → 导出带任务时间线的报告。
不把这一步扩展为任意 Shell 脚本平台；先组合受控、可清理的已有任务。

验收：报告明确哪些步骤成功、哪些失败，并可关联截图/视频/日志时间；再次运行复用配置，但不宣称网络流量完全重放。

## 3. 弱网场景和效果观测（已实现）

保存配置并支持分阶段场景（正常、高延迟、短时断网、恢复）。
为共享限速器和 UDP 队列增加观测：有效负载吞吐、连接数、配置丢包与队列溢出丢包分别统计。
报告区分配置值与实际测量值，标明 UDP-over-TCP 隧道对真实网络语义的影响。

验收：同一配置能够重复执行，并有数据解释“为什么实际体验与设置值不同”。

已提供本地场景保存、多阶段执行、独立配置快照、TCP/UDP 共享限速观测、分原因 UDP 丢弃和 JSON 报告。自动化已覆盖时钟、重放配置、限速、丢弃归因与隧道帧完整性；真实设备体验仍需实机验收。详见[弱网场景与效果观测](weak-network-scenarios.md)。

## 4. 应用性能与问题时间线

把设备整体概览扩展到目标应用的时间序列，关联会话标记和版本。
优先集成 Perfetto 采集和结果打开能力，而非自行实现完整 trace 分析器：
[Perfetto 系统跟踪](https://perfetto.dev/docs/getting-started/system-tracing)。
所有指标标明来源和可用条件；不同图形渲染方式不能直接套用同一种 FPS 统计。

## 5. 有真实需求后扩展多设备并行

目前同种任务全局仅一个实例，前端日志也只有一个数据仓库。
并行前需要将资源键改为“任务种类 + 设备”，给所有事件增加归属信息，并为历史、日志和采样制定内存/磁盘配额。
同时将历史持久化与进程监督从任务核心拆为独立模块，增加版本迁移和可选脱敏。

建议下一个产品增量选择“测试会话 + 报告”。任务中心已经提供其基础身份和生命周期，新增功能能直接利用现有代码。
